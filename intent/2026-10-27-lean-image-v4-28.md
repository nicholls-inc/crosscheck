# Intent: Upgrade the Lean image to Lean v4.28.0 and Mathlib v4.28.0

## Problem statement
The Lean image that `lean_check`, `lean_run` and `lean_test` use (`crosscheck-lean`) pins Lean `leanprover/lean4:v4.10.0` and Mathlib `v4.10.0` in `crosscheck/mcp-server/lean-harness/lean-toolchain` and `lakefile.lean`. That is 18 Lean releases behind. The rest of the repository has moved on: `cgv/prover` and `formal-verification/requirements` build with Lean v4.28.0. A model written for v4.28.0 fails in the image. For example, `List.Pairwise` is not in core at v4.10.0, so a file that uses it fails in the image with an unknown identifier although it builds with the repository's own toolchain.

## Proposed outcome
The image builds Lean v4.28.0 with Mathlib at the tag `v4.28.0`. A Lean file that builds with the v4.28.0 toolchain and Mathlib builds in the image, so `lean_check`, `lean_run` and `lean_test` judge the files the `/lean-spec` and `/lean-impl` pipeline now produces. The Mathlib oleans stay pre-warmed in the image, and a check of a small file stays inside the existing 240 s timeout and 2 GB memory limit.

## Affected users and systems
- Anyone who runs `/lean-spec`, `/lean-impl`, `/correspondence-review` or `/drt-oracle`: their models are now judged against v4.28.0.
- `crosscheck/mcp-server/lean-harness/` (`lean-toolchain`, `lakefile.lean`), the image built by `crosscheck/scripts/build-lean-docker.sh` from `crosscheck/mcp-server/Dockerfile.lean`.
- Existing Lean files that the image checks: `formal-verification/lean/CrosscheckModel/Power.lean`, which imports Mathlib. `formal-verification/requirements/**` builds with its own Lake package and does not use the image.
- Every host with a local `crosscheck-lean:latest` must rebuild the image with `crosscheck/scripts/build-lean-docker.sh`.

## Constraints
- No protected surface changes: no `SKILL.md`, agent, `docs/assurance/**`, CI or `*.test.ts` file.
- The Docker limits (no network at run time, 2 GB memory, 240 s timeout) do not change.
- The pin lives in two files that must agree: the toolchain file and the Mathlib tag in the lakefile.
- The local tag `crosscheck-lean:latest` is shared with other sessions, so this change is built and tested under a separate tag first.

## Open questions
- None that block the spec. Whether CI should build the Lean image to catch pin drift is not yet reached: no workflow builds it today.
- `crosscheck/skills/lean-spec/SKILL.md` line 88 tells models to `import Mathlib.Data.Nat.Defs`, a module that no longer exists at Mathlib v4.28.0 (`Mathlib.Data.Nat.Basic` replaces it). That file is a Class A protected surface. No item in `docs/assurance/ROADMAP.md` covers a Lean image or a `/lean-spec` import table, so `/protected-surface-amend` refuses (its Step 5), and this change does not edit the file. The follow-up needs a roadmap item first.
