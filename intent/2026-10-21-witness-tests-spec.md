# Spec: Witness tests run each counterexample against the target field

Intent: `intent/2026-10-21-witness-tests.md`. Governing roadmap item: CG-1. Task: CG-1.37.

A *witness error* is a checker result whose severity is `error` and that carries a `counterexample` (WT-8). Its *target field* is the node named by the result's `target` (name, file and line). A *witness module* is a file the generator writes.

- **WX-1. The flag.** `contracts check --witness-tests DIR` writes witness modules into DIR, creating it if it does not exist. It acts whenever the checker printed a JSON result that `report::parse` reads, in either `--format`, with or without `--baseline`, `--write-baseline` and `--evidence-record`. It writes modules for every witness error of the run, not only the errors that are new against a baseline. The flag changes neither stdout nor the exit code, except that a failure to clear or write DIR prints an error on stderr and exits 2. It prints one line on stderr: `wrote N witness test module(s) to DIR`, followed by `; M witness error(s) not yet reached (...)` when some witness errors get no module, with a count per reason of WX-2.
- **WX-2. Which errors get a module.** A witness error gets exactly one module when (a) the extractor recorded its target node as a field that its library validates at run time (WX-3), and (b) its counterexample matches the grammar of WX-4. The reasons for none are `target not enforced at run time` (a data class, attrs, `NamedTuple` or `TypedDict` field, a pydantic field that skips validation, a parameter or a return annotation), and `counterexample text not recognised`. Other results get none.
- **WX-3. Which library declared a field.** The contract database gains a table `field_origins` with one row per `model` node that a class field produced: `node_id`, `library` (one of `django`, `pydantic`, `dataclass`, `attrs`, `namedtuple`, `typeddict`), `module` (the dotted module name of the class, relative to the checked path), `class_name`, `field_name`, and `validated`, which is 1 for every Django field and for a pydantic field that the extractor does not mark `unvalidated` (`SkipValidation`, a `PlainValidator` or `WrapValidator`, or a `None` default under an annotation without None), and 0 otherwise. A field inherited from another model is recorded under the child class that the node names. The Lean checker does not read the table.
- **WX-4. Counterexample grammar.** The generator writes a counterexample into Python source only when its text is one of: `None`; an integer literal (`-?[0-9]+`); `Decimal("<d>")` where `<d>` is `-?[0-9]+(\.[0-9]+)?`; `"x" * <n>` where `<n>` is `[0-9]+`; or a double-quoted string literal whose characters are printable ASCII other than `"` and `\`, or one of the escapes `\\`, `\"`, `\xNN`, `\uNNNN`, `\UNNNNNNNN` with lowercase hex digits (WT-6). A counterexample is *fractional* when it is `Decimal("<d>")` and `<d>` has a `.`.
- **WX-5. File names.** Modules are numbered in the order of the checker's results, from 1, and named `test_cgv_witness_<NNN>_<slug>.py`: `<NNN>` is the number, zero-padded to three digits, and `<slug>` is the target's name in lowercase with each run of characters outside `[a-z0-9]` replaced by `_`, trimmed of `_`. A helper module, `_cgv_witness.py`, is written beside them when at least one module is written. It defines `APP_ROOT`, the absolute checked path, and `DJANGO_MODULES`, the sorted module names of every Django field in `field_origins`. Each file DIR receives starts with the line `# Generated by crosscheck-contracts --witness-tests (CG-1.37). Do not edit.`
- **WX-6. Earlier output.** Before writing, the generator removes each file directly in DIR whose name is `_cgv_witness.py` or starts with `test_cgv_witness_` and ends with `.py`, and whose first line is the marker of WX-5. It removes nothing else. So a run with no witness module leaves DIR without generated files, and two runs on the same input leave the same files.
- **WX-7. The target test.** Each module defines `COUNTEREXAMPLE`, assigned the counterexample text, and `test_target_accepts_counterexample`, which passes the library, module, class and field names and `COUNTEREXAMPLE` to the helper. The helper imports the class and takes the field (WX-9, WX-10). If the counterexample is fractional and the field is integral, it skips the test with a reason that starts `CGV-WITNESS WITHHELD` and names the gap of the intent. Otherwise it runs the field's validation. If that raises the library's `ValidationError`, the test fails with a message that starts `CGV-WITNESS REJECTED` and names the library and its version, the field, the counterexample, and the rejection codes in the order the library reports them. If it returns, the test passes. Any other exception fails the test without the marker.
- **WX-8. The source test.** When the result's `source` node is itself recorded in `field_origins` as a Django or pydantic field, the module also defines `test_source_accepts_counterexample`, which runs that field's validation in the same way and fails with a message that starts `CGV-WITNESS SOURCE REJECTED` when it rejects, saying that the counterexample is then no witness. It is withheld, with no test function and a comment that names the gap, when the source guarantee is a `range` or `range_min` bound (until CG-1.40 item 5) and, at run time, skipped like WX-7 when the counterexample is fractional and the target field integral.
- **WX-9. Django.** The field is `Model._meta.get_field(field_name)` and its validation is `field.clean(value, None)`. The helper puts the checked path first on `sys.path`. If `DJANGO_SETTINGS_MODULE` is set, it calls `django.setup()` with the user's settings. Otherwise it configures settings with `USE_TZ=True` and no installed apps, calls `django.setup()`, and registers, for each module of `DJANGO_MODULES` that no app contains, an app whose name is the module's name and whose label is `cgv_witness_` followed by the module name with each non-word character replaced by `_`, so that a model module may import models from another. It does the same before importing a pydantic model's module when Django is installed, since that module may declare Django models too. A field is integral when it is an instance of `django.db.models.IntegerField`.
- **WX-10. pydantic.** The field is `Model.model_fields[field_name]`, and its validation is `TypeAdapter(Annotated[annotation, *metadata]).validate_python(value)`, with `ConfigDict(strict=True)` when the model's config sets `strict`. A field is integral when its annotation is `int` or `Optional[int]`.
- **WX-11. Strength text.** Each module's header comment gives, with line breaks flattened, the error's path, source guarantee, target requirement, target field and counterexample, and says: the counterexample is proved by the Lean checker to be admitted by the source bound and rejected by the target bound, relative to the translated constraints; a failure marked `CGV-WITNESS REJECTED` is tested evidence, on this one value and the library version the message names, that the target field rejects it; a pass means the library accepted it, which is no evidence for the error; neither shows that the code produces the value (CG-1.39).
- **WX-12. The fixture run.** `cgv/scripts/witness_tests.py run` builds a virtual environment for each of `scripts/witness-requirements-django42.txt` and `scripts/witness-requirements-django52.txt` (Python 3.12, hashes required), runs `contracts check --witness-tests` on every fixture under `test_fixtures/` with an `expected.json`, runs pytest on the modules of each fixture with each environment, and exits 0 only when every target test failed with `CGV-WITNESS REJECTED` or was skipped with `CGV-WITNESS WITHHELD`, every source test passed, the fixture `witness_tests` has a rejected module of each WT-1 kind and of each library, and `witness_tests_clean` produced none. A fixture listed in the script's `IMPORT_GAPS` imports a package the environments do not pin, and each of its tests must instead fail with `ModuleNotFoundError` for exactly that package. Any other outcome, including a collection error, exits 1, naming the fixture, module and outcome. `cgv/scripts/witness_tests.py selftest` writes the modules of `witness_tests`, replaces the counterexample of one module per WT-1 kind with a value its field accepts, and exits 0 only when the run then fails on exactly those modules. CGV CI does not run them yet: CG-1.55 adds the steps.

**Known gaps, not rules.** The gaps of the intent's "Not yet reached" section: the source assertion has no source to run on today, a fractional counterexample against an integral field is withheld, pydantic field and model validators do not run, unenforced targets get no module, and a module that does not import on its own fails without the marker (`IMPORT_GAPS`).
