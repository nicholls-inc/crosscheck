# Spec: The conformance ledger fails when `claims.json` cannot be read or parsed

Intent: `intent/2026-10-07-ledger-load-fails-closed.md`. Governing roadmap item: PB-1. Task: PB-1.23. PB-1.24 amends LL-1, LL-6 and LL-7 and adds LL-8 (`intent/2026-10-07-ledger-dangling-symlink.md`). PB-1.30 amends LL-1, LL-4, LL-6 and LL-7 and adds LL-9 (`intent/2026-10-07-ledger-missing-root.md`).

- **LL-1. Missing file.** When reading `<root>/conformance/claims.json` fails with an error that `errors.Is(err, fs.ErrNotExist)` accepts, and neither LL-8 nor LL-9 applies, the ledger is empty and `analyze` adds no ledger error.
- **LL-2. Unreadable file.** When the read fails with any other error, `analyze` appends one error, `[ledger] cannot read conformance/claims.json: <error>`, and the ledger is empty. A path that is a directory and a file without read permission are both in this case.
- **LL-3. Invalid content.** When the file is read but `json.Unmarshal` into the ledger shape fails, `analyze` appends one error, `[ledger] cannot parse conformance/claims.json: <error>`, and the ledger is empty. An empty file, truncated JSON, and a `narrative_claims` value that is not an array are all in this case.
- **LL-4. Exit code.** An LL-2, LL-3, LL-8 or LL-9 error is an ordinary error, so `report` prints `RESULT: FAIL`, which `main` maps to exit 1 as for any other error.
- **LL-5. Existing rules stand.** A ledger that decodes runs the status, `unreviewed`, `known-gap` and `present_artifact` checks as before, with the same messages.
- **LL-6. Documentation.** The header comment of `main.go` and `crosscheck/conformance/README.md` say that a missing `claims.json` is an empty ledger and that one that cannot be read or parsed, including a symlink to a missing target at `claims.json` or `conformance`, is an error, and that a plugin root that does not resolve is an error.
- **LL-7. Tests.** `TestLedgerLoad` in `main_test.go` builds a tree per case and asserts the error for a directory at the path, a mode-000 file (skipped when the process runs as root, which can read it), truncated JSON, an empty file, and a non-array `narrative_claims`, a decode that returns claims and then fails (`partial_decode`), a `claims.json` symlink to a missing target (`dangling_symlink`), a `claims.json` symlink to a symlink to a missing target (`dangling_symlink_chain`), and a `conformance` directory that is a symlink to a missing target (`dangling_conformance_dir`), and asserts that each of them makes `report` print `RESULT: FAIL` and leaves the ledger empty. It asserts no ledger error for a missing file and for a missing `conformance/` directory, that a `conformance` directory symlink to an existing directory with no `claims.json` (`conformance_dir_symlink_no_ledger`) is an empty ledger, and that a `claims.json` symlink to a valid ledger (`symlink_to_ledger`) loads its claims with no error. For the three dangling-link cases it asserts that the error `loadLedger` returns wraps `fs.ErrNotExist`. `TestLedgerLoadRoot` asserts the LL-9 error, `RESULT: FAIL`, and an error that wraps `fs.ErrNotExist` for a root that does not exist (`missing_root`), a root that is a symlink to a missing target (`dangling_root`), and a root under an ancestor that is a symlink to a missing target (`dangling_ancestor`). It asserts a pass for an empty root directory (`empty_root`) and for a root that is a symlink to a plugin tree with no `claims.json` (`root_symlink_to_tree`). Restoring the old `loadLedger`, which returns no claims on any failure, fails every error case.
- **LL-8. Dangling symlink.** When the read fails as in LL-1, but `<root>/conformance/claims.json` or `<root>/conformance` is a symbolic link whose target, followed to the end, does not exist, `analyze` appends one error, `[ledger] cannot read conformance/claims.json: <path> is a symbolic link to a missing target: <error>`, and the ledger is empty. A dangling link is a ledger someone put in place and broke, so it is unreadable, not missing.
- **LL-9. Root does not resolve.** When the read fails as in LL-1, LL-8 does not apply, and `os.Stat` on the plugin root fails, `analyze` appends one error, `[ledger] cannot read conformance/claims.json: plugin root <root> does not resolve: <error>`, and the ledger is empty. This covers a root that does not exist, a root that is a symlink to a missing target, and a root below an ancestor that is one. `os.Lstat` on a path under such a root fails, so LL-8 cannot see these links. A run under such a root scans nothing, so it must not pass.
- **Known gaps, not rules.**
  - JSON that decodes but carries unknown keys, or a top-level `null` or `{}`, is a valid empty or partial ledger. Nothing checks the schema of `claims.json`. Queued as PB-1.25, which adds a schema check.
