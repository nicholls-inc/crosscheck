Spec Kit: 28 reported defects

AboutA study of 28 defects reported in Spec Kit, GitHub’s toolkit for spec-driven development.

Spec Kit (opens in a new tab) is GitHub’s open-source toolkit for spec-driven development. It sets up a project so that an AI coding agent works from a written specification, a plan and a task list.

Its command-line tool, specify, also installs extensions, presets, bundles and workflows, and wires them into each supported coding agent.

On 23 October 2026, Harry filed 28 defect reports against Spec Kit 1.2.4.dev0. This study lists them, how each was checked, and what happened upstream.

Each piece of evidence has one of five strengths: Proved, Tested, Decided by Harry, Assumed or Not yet reached. Nothing here is Proved. The defects were tested, one reproduction at a time.

The workflow expressions study looks more closely at three of the reports.

Findings

What was found?

28 defects in Spec Kit, GitHub’s toolkit for spec-driven development with AI coding agents. They cover workflows, extensions, presets, bundles, agent integrations and the command line.

Most are quiet failures. A command reports success, or a condition takes the wrong branch, with no error.

Each report names the line of Spec Kit’s own documentation, docstring, test or sibling code that the behaviour contradicts. Two reports infer the expected behaviour instead.

How were they found?

In one Claude Code session on 22 October 2026. CGV ran first, over Spec Kit’s source. Its 39 errors turned out to hold no real bug.

Then eight subagents each searched one part of the source, following Crosscheck’s /reason method. A finding counted only when a script reproduced it.

31 findings became the 28 reports. Six more were left out because an open issue or pull request already covered them.

Are the defects real?

Each report has a reproduction script and the output it gave at Spec Kit commit 27d14e2. Two agents ran each script in the session that found it, and each report states that the reporter re-ran it before filing.

Spec Kit’s maintainers triaged all 28 as in scope. 19 now have a merged fix.

This website did not rerun the reproductions.

Checks

How the defects were found

. Session transcript and reports · Tested, Decided by Harry

Only the reproductions count as evidence. The agents’ reasoning pointed at where to look.

A Claude Code session on 2026-10-22, from 23:29 to 23:59 UTC, against Spec Kit at the filing commit. The transcript is not public. The requests that started it read:

  • “Now clone https://github.com/github/spec-kit and run CGV and Crosscheck on it. Orchestrate parallel subagents.”
  • “Draft them in a file”
  • “Also check if our findings match any open issues.”

CGV ran first. Then eight subagents each searched one slice of Spec Kit’s source for defects: Workflows core; workflow commands and steps; integrations; extensions; presets; bundles and artifacts; security, events and authentication; top-level modules and scripts.

A finding counted only when a reproduction script’s actual output showed the wrong behaviour. A finding argued from reading the code alone was dropped or marked unconfirmed. Each subagent followed the certificate steps of Crosscheck’s /reason skill: premises with file and line, traces, and checks of alternative explanations. Those certificates are an AI agent’s reasoning, so they are not evidence; only the reproductions count.

The main agent re-ran every reproduction script from the eight subagents. When drafting, each subagent made its reproduction self-contained and ran it again as written, and the main agent then ran all of them once more. Four findings about unsupported expression syntax became one report, #5073, so 31 findings became 28 reports.

A tenth subagent listed the titles of all 81 open issues and 98 open pull requests, ran two to six full-text searches for each finding and read every candidate. GitHub search does not cover comments or diffs.

The container had no Docker daemon, so Crosscheck’s Dafny and Lean pipelines did not run.

Each report records its reproduction’s output, from a Linux container and from macOS:

  • Linux 6.18 (Ubuntu container), Python 3.12.3
  • macOS (Darwin 25.6, arm64), Python 3.14.4

Every report names Spec Kit 1.2.4.dev0 at 27d14e2 (opens in a new tab) and ends: “Found and reproduced with Claude Code, run autonomously under human supervision. The human reporter re-ran every reproduction above before filing.”

All 39 errors are nullability errors, most where a workflow step passes a value that may be None to the expression evaluator. A triage agent sorted the 37 distinct sites: 0 real bugs, 11 where only the type annotation is wrong, and 26 false positives where CGV missed a check that rules out None. Four of the false positives come from a defect in CGV’s extractor, which binds a function-local import to the wrong function. CGV found none of the 28 reported defects. The triage verdicts are an AI agent’s judgement, so they are not evidence that any site is safe; only the counts come from CGV itself. An exit code of 1 means only that the extracted graph has these errors.

What each report is measured against

. Reports · Assumed

Where Spec Kit’s documentation and its code disagree, either could be the one that is wrong.

No report rests on an outside opinion of how Spec Kit should behave. Each one quotes Spec Kit’s own statement of the behaviour: a docstring, a page of its documentation, a test, a code comment, or another code path that handles the same input differently.

That is an assumption. A report shows that code and statement disagree. It does not show which one the maintainers meant. In #5083 the fix that is open changes the documentation, not the code.

Two reports, #5097 and #5098, find no written statement and infer the expected behaviour from nearby code. Each says so.

Limits

What wasn’t checked?

The constraints most of these defects involve. CGV has no way to state rules about strings, paths or the shape of a dictionary, and Dafny and Lean did not run.

Whether each defect still reproduces on Spec Kit’s main branch. Upstream merged fixes are the maintainers’ evidence, not this study’s.

How much any defect matters to users. The study has no usage data.

Can I run a reproduction myself?

Yes. Each report gives its steps. You need git, uv and Python 3.12 or later.
